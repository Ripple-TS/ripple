Cheaper component instantiation and `@if` chains on the client. A component call site with a reactive prop now compiles to an instance of a props class built once per call site shape (`_$_.props_site`): the props are prototype getters, the instance holds only the captured locals and static values in symbol slots, and construction is one allocation with no per-property runtime call and no per-getter closure. A reactive prop expression built only from the component's own `props`, constants and captured values is evaluated once and kept when that evaluation read no tracked state, so a prop forwarded down a component tree stops re-evaluating the whole getter chain on every read. Every component now receives a `Props` instance: a call site with only static props compiles to the class as well, a spread site merges its sources into a per-site class (the spread Proxy is gone; a tracked object as a spread source keeps a Proxy-backed instance under the same prototype), `mount()`/`hydrate()` build an instance from their `props` option, and the rare site whose expressions cannot live at module level keeps its closure getters under the `Props` prototype. A `let` that is reassigned later and read by template code is boxed so hoisted code reads its current value. Because the props are prototype getters, `Object.keys`, `Object.values`, `Object.entries`, object spread and rest destructuring of props in `.tsrx` code compile to props-aware helpers, props serialize through `toJSON`, and code outside the compiler reads props through the `Props` helpers exported from 'ripple' (`keys`, `ownSymbolKeys`, `ownAllKeys`, `values`, `entries`, `has`, `spread`, `rest`), which accept compiled props and plain objects alike. A lazy pair's `Tracked` alias passed as a prop is a static value rather than a getter. An `@else if`, and a branch whose only statement is another `@if`, fold into the enclosing `@if` block on both the client and the server, so a chain costs one block and one hydration boundary. An `@if` whose condition reads no tracked state renders its branch directly under the enclosing block with no block of its own (a block without dependencies is never scheduled, so nothing is lost); a dynamic condition keeps its block and adopts the dependencies recorded while it was evaluated. A module-level component also carries a direct render entry so `render_component` skips the element it would otherwise return. An `@if` condition and its branches compile to module-level functions when they capture at most one local (passed through the if runtime), a condition returns the branch function to render instead of calling a selection callback, and a render block's function is module-level with its captured locals carried on the block state, so a component instantiation creates no closures for its ifs or its reactive text and attribute updates. `Context.get()` walks a chain of the context entries that were set rather than every ancestor component. A module-level component's render body is a module-level function that receives the props from the element instead of a closure created per instantiation, `Context.get()`/`set()` calls on a `new Context()` binding skip the `with_scope` wrapper, and `mount()` only schedules the SSR style removal when the page has server-rendered inline styles.
